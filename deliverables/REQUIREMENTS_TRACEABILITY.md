# Assignment requirements traceability

Status terms are intentionally strict:

- **DELIVERED** — the requested reviewer artifact is present and validated in
  this package or the linked repository.
- **LIVE-PROVEN** — demonstrated by the deployed release and the dated
  evidence snapshot.
- **SOURCE-READY** — implemented and locally or statically verified, but not
  enabled or claimed as a live control.
- **DOCUMENTED DEVIATION** — the literal requested mechanism or a complete
  fresh-environment proof differs; the substitute and consequence are stated.

## Architecture and operational requirements

| Assignment area | Status | Exact implementation, proof, and boundary |
|---|---|---|
| Project governance and IAM for Dev, Ops, SRE, and CI/CD | **DELIVERED / LIVE-PROVEN / DOCUMENTED DEVIATION** | The dedicated project has a $30 alerting budget. Dev has repository/lower-environment access and no production principal; Ops is the disclosed standing project Owner; SRE uses the read-only dashboard identity; CI/CD uses one shared builder plus namespace-scoped App A/App B deployers. Own-versus-peer and privileged-action denials were live-proven. The personal account has no Organization/Folder or Cloud Identity groups, so the literal Folder -> Project hierarchy and enterprise group inheritance are not implemented: [`ARCHITECTURE.md`](ARCHITECTURE.md), [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md), and [`EVIDENCE.md`](EVIDENCE.md). |
| VPC, private clusters, egress, DNS, firewall, and internal routing | **LIVE-PROVEN / DOCUMENTED DEVIATION** | Two private-node, VPC-native regional Autopilot clusters use one dedicated subnet plus Pod/Service ranges per cluster, Private Google Access, an administrator-only control-plane `/32`, health-check firewall ingress, and cell-local App B ClusterIP routing. Cloud DNS serves the public edge; Kubernetes DNS resolves App B inside each cell. Separate load-balancer and monitoring/ops subnets are unnecessary for this global external Application Load Balancer and ephemeral in-cluster observability Job. ClusterIP replaces the suggested internal load balancer because App A and App B are in the same cluster/cell and make no cross-cluster east-west call. Shared VPC, Private Service Access, Cloud NAT, and a default-deny egress policy were not added because this stateless design has no managed private-service or arbitrary internet-egress requirement; Google metadata/signing/telemetry destinations need a reviewed FQDN-aware egress design: [`ARCHITECTURE.md`](ARCHITECTURE.md) and [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md). |
| Two regional GKE cells, two web applications, replicas, HPA, and rolling deployment | **LIVE-PROVEN** | Public Java App A and private .NET App B run in both regions with multiple Pods, HPA v2, PDBs, hardened containers, and RollingUpdate configured with `maxUnavailable: 0` and `maxSurge: 1`. That rollout setting is not presented as a zero-downtime regional-failover guarantee. App A is zonally sharded to populate six Pod NEGs; App B is topology-spread and cell-local. Immutable full-SHA images and exact ready replicas were gated in both cells: [`ARCHITECTURE.md`](ARCHITECTURE.md) and [`EVIDENCE.md`](EVIDENCE.md). |
| Global HTTPS distribution, regional resilience, and recovery | **LIVE-PROVEN / DOCUMENTED DEVIATION** | One global HTTPS-only load balancer routes to six zonal Pod NEGs and drains a cell when its cached local App B health fails. The measured exercise shifted new traffic to the survivor, restored its reversible fault configuration, and recovered all six backends. This is bounded automatic recovery, not zero downtime or a one-region peak-capacity proof. The stateless apps have no database, PV, or application state in etcd. Terraform, Kustomize, source, and immutable images provide rebuild inputs; stateful production recovery would need explicit replication, retention, and restore tests: [`ARCHITECTURE.md`](ARCHITECTURE.md) and [`EVIDENCE.md`](EVIDENCE.md). |
| Logging, Monitoring, BigQuery, Grafana, and Error Reporting | **LIVE-PROVEN** | The immutable release proves structured App A/App B logs, the partitioned application sink, parameterized SQL, grouped application exceptions, and four populated Grafana panels. The separate bounded platform sink and live gates cover GKE control-plane/node/HPA, load-balancer, VPC-flow, and firewall logs plus node health and HTTPS request/5xx/latency metrics: [`EVIDENCE.md`](EVIDENCE.md), [`BIGQUERY.md`](BIGQUERY.md), and [`grafana-dashboard.png`](grafana-dashboard.png). |
| Cloud Trace and Cloud Profiler | **LIVE-PROVEN / DOCUMENTED PARTIAL** | Direct keyless sampled export proved the exact App A server -> App A client -> App B server parent chain for the current release. Java App A produced current CPU and HEAP profiles across all six configured zones. There is no .NET App B profiling claim, and sampled traces are not an audit record: [`EVIDENCE.md`](EVIDENCE.md) and [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md). |
| Security controls | **LIVE-PROVEN / SOURCE-READY / DOCUMENTED DEVIATION** | Live proof covers Workload Identity, exact audience/caller authentication, private App B, restricted Pod Security, NetworkPolicy, namespace RBAC, immutable images, HTTPS-only ingress, no service-account keys, and no application Secrets. Guarded cloud/Terraform entry points reject alternate token, credential-file, ADC, and impersonation overrides. Cloud Armor and Binary Authorization are implemented opt-ins but disabled and not claimed live. The internal hop is authenticated HTTP, not mTLS; the stateless apps have no secret or volume requiring Secret Manager or backup. See [`ARCHITECTURE.md`](ARCHITECTURE.md), [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md), and [`EVIDENCE.md`](EVIDENCE.md). |

## Literal requirements and stated deviations

| Item | Status | Exact boundary and consequence |
|---|---|---|
| Global routing through MCI/MCS and GKE Ingress | **DOCUMENTED DEVIATION** | The solution uses a Terraform-managed global external Application Load Balancer with six standalone zonal Pod NEGs instead of MCI/MCS. It also has no GKE Ingress controller: App A Services register the NEGs and the Terraform backend routes directly to the Pod endpoints. This preserves one global HTTPS endpoint, pod-native backends, health-based regional draining, and measured failover, but it does not claim either literal product path. See [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md) and [`ARCHITECTURE.md`](ARCHITECTURE.md). |
| Cloud-hosted Grafana | **LIVE-PROVEN / DOCUMENTED DEVIATION** | Grafana ran inside private GKE as a one-hour keyless Job from one scanned Artifact Registry digest, with the signed BigQuery plugin baked in and no runtime download. Operator loopback avoided an anonymous public endpoint. This satisfies cloud hosting for evidence, but it is not durable shared hosting with HTTPS ingress, SSO, persistence, backups, or an availability budget. |
| Cloud Trace and Profiler observability | **LIVE-PROVEN / DOCUMENTED PARTIAL** | Direct keyless sampled traces proved the current App A-to-App B chain. Java App A Profiler proved current CPU and HEAP coverage; no .NET App B profiler is claimed. See [`EVIDENCE.md`](EVIDENCE.md) and [`DESIGN_DECISIONS.md`](DESIGN_DECISIONS.md). |
| Terraform-only application deployment | **DOCUMENTED DEVIATION** | Terraform owns project/GCP resources; Kustomize owns namespaced Kubernetes workloads and policy. Guarded scripts connect the ordered phases. This avoids Terraform managing frequently changing Deployment objects, but reproduction requires both toolchains. See [`SETUP.md`](SETUP.md) and public [`k8s`](https://github.com/satish34/Schwab_Assessment/tree/main/k8s). |
| Creation of project, billing relationship, and public DNS delegation | **DOCUMENTED DEVIATION** | An existing billing-enabled GCP project and owned domain are prerequisites. Terraform adopts the project, creates the Cloud DNS zone/certificate resources, and prints name servers; billing attachment and registrar delegation remain account-level manual actions. See [`SETUP.md`](SETUP.md). |

## Evidence integrity boundary

The package’s screenshots, Grafana export, live schema, SQL, and static diagram
images are covered by [`SHA256SUMS.txt`](SHA256SUMS.txt). The package contains no
credential, service-account key, token, kubeconfig, Terraform state,
assignment PDF, raw log export, or raw failover request dataset.
