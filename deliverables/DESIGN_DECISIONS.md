# Design decisions and tradeoffs

| Decision | Reason and honest tradeoff |
|---|---|
| Synthetic, no-input currency board | The public demo needs no login, customer data, form, body, query, or external market feed. Ten fixed snapshots are deterministic and still exercise App A to App B on every refresh; this is not a market-data product. |
| Java App A; .NET App B | Matches the assignment technology split. Only App A is public; App B is a local ClusterIP in each regional cell. |
| Network restriction plus workload authentication | App B ingress NetworkPolicy narrows the reachable path, while a Google-signed ID token proves the exact App A caller and audience. Either control alone is weaker. The hop remains HTTP, so production should add mTLS where internal transport confidentiality or replay resistance is required. |
| Separate namespaces, KSAs, and deployers | Each app team can update only its Deployments, HPAs, and PDBs; it cannot access the peer namespace, Secrets, exec/attach, RBAC, policies, or platform Services. Shared project/cluster/build/registry boundaries mean this is trusted-team isolation, not hostile tenancy. |
| No production Dev identity | Code reaches production through review and CI/CD rather than standing developer credentials. Ops still has broad Owner access in this single-operator assessment; production should separate duties and use privileged access management. |
| Hardened Pods by default | Restricted Pod Security, non-root users, read-only roots, dropped capabilities, no privilege escalation, RuntimeDefault seccomp, quotas, and explicit ingress policies make the security posture verifiable in manifests and live RBAC gates. Default-deny egress is deferred because required Google identity/telemetry destinations need an explicit egress design first. |
| Regional Autopilot with fixed zones | Desired placement is central `b/c/f` and east `a/b/c`, producing deterministic zonal shards and six NEGs. The 96-vCPU quota preference is only a ceiling: it reserves no capacity and cannot prevent provider capacity failures. Fixed zones also reduce scheduler flexibility. |
| One Terraform edge with six standalone Pod NEGs | Keeps the complete global load-balancer graph reviewable in Terraform without Fleet/MCI/MCS. Kubernetes must create and populate the NEGs before the final Terraform stack, so orchestration is stricter. |
| Active-active health-based routing | Either healthy cell can serve. A cached background App B probe controls `/health/cell`, while Pod readiness stays independent of App B. Recovery is simple and measurable, but health convergence caused bounded transition errors and is not strict primary/secondary or zero downtime. |
| Managed TLS on port 443 only | Cloud DNS and Certificate Manager avoid private keys in Terraform and automate renewal. Registrar delegation remains manual, and mistyped plain HTTP fails rather than redirects because there is no port-80 frontend. |
| Stable structured application log schema | Application-only stdout export keeps BigQuery queries and Grafana panels predictable. The release proves both log-based cross-service correlation and a separate exported distributed-trace chain. |
| Direct Trace export, no collector | Each workload sends sampled spans directly through a keyless identity, avoiding a standing collector Pod and its availability/cost surface. The live gate proved the App A server -> App A client -> App B server parent chain. Export remains asynchronous and 10% sampled, so it is diagnostic rather than an audit record. |
| Java Profiler only | The live gate found current App A CPU and HEAP profiles across all six configured zones. Profiling remains independent of request correctness, and no equivalent .NET App B profile path is claimed. Evidence retains metadata only, not profile bytes. |
| Private one-hour GKE Grafana | Running Grafana as a Job inside GKE satisfies cloud hosting without exporting a service-account key to an external SaaS. A dedicated build bakes the checksum-pinned BigQuery plugin into a scanned Artifact Registry image; the Job resolves one release digest and downloads nothing at runtime. Workload Identity gives it keyless read-only access. Operator loopback avoids an anonymous public endpoint, so the evidence session has no shareable internet URL. A durable team service would add HTTPS ingress, SSO/group authorization, persistent configuration, patching, backups, and an availability/cost budget. |
| Separate bounded platform-log sink | A dedicated 30-day dataset separates variable platform schemas from the stable app table. Five-percent VPC/LB sampling and ten-percent selected control-plane/node/firewall sampling bound volume. The live gate proved current delivery and metrics, but sampling remains unsuitable for complete forensic accounting. |
| Cloud Armor and Binary Authorization opt-in | Both controls are implemented behind flags but were disabled in the evidence snapshot to avoid unapproved feature cost. Therefore there is no live WAF/rate-limit or admission-enforcement claim. Repository allowlisting, if enabled, is not signed attestation. |
| Existing billing-enabled project and local Terraform state | Terraform declaratively adopts the project rather than creating/deleting the billing relationship. A new empty-project deployment creates four local states; they preserve ordered teardown but lack remote locking and durable recovery. An existing quota preference requires import, and populated projects require complete resource adoption. Production needs a separately bootstrapped encrypted/versioned backend. |

Retained `risk-*` infrastructure names predate the currency demonstration.
Renaming them would replace healthy shared resources without improving the
architecture; business-facing documentation and namespaces use current
currency terminology.
